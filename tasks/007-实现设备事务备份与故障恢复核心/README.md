## 输入、动作、产物

输入为稳定身份/挂载代次/能力版本、数据库 profile、源文件与不可变计划。实现独立 Core、受目录约束的文件系统、恢复记录、备份保留与故障注入。所有运行只使用电脑测试目录及合成数据库。

007 验证正常导入/删除/初始化、取消、存储失败、进程中断后的恢复及恢复自身中断。后续 008 接入媒体/服务写入口并单独授权实机；当前 foobar 服务继续拒绝写入。

005 尚有 DUP-001；不伪造其已验收。用户此次授权使 007 的离线核心可先行；真实写入前必须解决设备身份歧义及 005 的相关门槛。

## 2026-09-23 集成阶段结果

已加入只读恢复记录分类：设备卷上的 `.foopodbridge/*.journal` 会被检查为待恢复、已完成或损坏；损坏记录保留证据并进入 `RecoveryRequired`，不会被当作空设备。设备状态描述现在报告待恢复与损坏记录数量。

已加入完整基线枚举与证明：自动递归枚举 `iPod_Control` 下的普通文件，拒绝重解析点、缺失/额外文件、目录重叠和枚举变化；证明绑定任务 ID、稳定设备身份、挂载代次、能力版本、源目录和外部备份目录。证明过期或身份变化时恢复被拒绝。

已加入离线 `recovery_session`：可检查恢复记录和快照、验证外部基线、加载经过 LKG 校验的数据库并复用事务引擎恢复。当前组件服务尚未发布可执行恢复操作的 ABI/UI；因此仍不开放设备写入。

同轮后续已在 Preferences → Tools → FooPodBridge 加入 `Directory recovery...` 入口。它只处理电脑 NTFS 普通目录副本，支持后台扫描、完整基线核验、恢复未完成事务和选择已标记 LKG；它不向当前连接的 iPod 发出写入，不能取代真实卷身份/授权服务。外部 FooCrate 消费的恢复 ABI 仍待实现。

交付候选：`dist/FooPodBridge-0.1.0-beta.5.fb2k-component`。首个人工检查只安装到 `foobar-test` 并打开该入口，暂不执行目录恢复，后续使用保留的合成 fixture 分步验证。
