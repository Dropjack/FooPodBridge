# 007 核心规格

## 2026-09-23 集成阶段

用户已授权继续实现恢复发现、终端用户恢复入口和完整基线门禁。当前阶段的写入验证仍只使用电脑目录，真实设备写入授权仍由后续点名任务提供。

恢复发现必须只读，区分完成标记、待恢复记录与损坏记录；损坏记录不能被当作无事务。恢复入口使用已验证记录，不按日期猜测恢复点。选择 Last Known Good 后仍需验证数据库及媒体引用，并经核心事务执行。

完整基线核验自行枚举整个 iPod_Control；拒绝重解析点、缺失或额外文件、重叠备份目录、身份或挂载代次变化。核验结果绑定任务、设备身份、挂载代次、能力版本和外部目录，不能单凭文件内容相同开放真实设备写入。

正式恢复入口遵循 DEC-REF-001；beta.7 移除自行新增的 Directory recovery 开发参数表单。服务层应自动关联已识别设备身份、数据库 profile、私有恢复仓库和备份，用户查看恢复状态并选择经过验证的恢复点，不手填设备仓库键或签名参数。离线目录恢复保留在 Core 和 fixture 中；真实卷门禁、授权提供器及跨组件服务尚待接入。原版孤立歌曲恢复与事务回滚的区别见 REFERENCE_RECOVERY.md。

## 用户可见语义

事务确保数据库提交前不删除旧音频，新增文件完成后才让新数据库引用它们。提交前取消保持旧库；提交窗口中取消延迟到安全边界。结果区分未提交、已提交、清理待办和必须恢复，不能把已提交报告成“完全取消”。

恢复点只有数据库，不包含歌曲。恢复旧数据库必须验证其引用的媒体仍在；删除完成后，旧快照可能只具有历史证据价值，不能承诺单靠它恢复已删除音乐。首次完整外部基线用于恢复当时整个曲库。

## 输入与权限

不可变计划记录物理身份的本地不透明键、挂载代次、能力版本、数据库路径/旧指纹、操作 ID、新库、新增和删除文件，以及空间安全余量。执行重新检查身份、代次、能力、旧库指纹和空间；使用全进程互斥锁，忙时明确拒绝。只读/未知能力和 PreserveOnly profile 拒绝写入，hash58 必须提供签名密钥。数据库输入沿用 Reader 的 512 MiB 上界，FAT32 单个媒体文件上限 0xffffffff 字节；超限在计划阶段拒绝。

Core 接受可信 database 适配器进行 profile/签名/引用校验；不通过文件名选择 Writer。007 提供传统/hash58 数据库适配器；多数据库家族没有对应完整验证器时不得写入。初始化必须是显式 InitializeLibrary 且库不存在，不因读取失败、损坏或插入设备而初始化。

电脑测试文件系统限定已有普通目录，拒绝根卷、重解析点、绝对路径、父目录跳转、设备名及 NTFS 流路径。当前不提供真实卷写入适配器。路径均是相对路径，临时名含操作 ID，创建不覆盖已有文件。

真实卷只读基线核验使用独立的只读目录入口，可打开 Windows 已挂载的固定盘或可移动盘卷根，拒绝重解析点及全部创建、追加、Flush、改名和删除操作。核验期间调用方持续提供当前物理身份与挂载代次；身份变化、文件树变化或内容差异均拒绝。本阶段只返回文件数和总字节数的核验摘要，不产生可用于设备写入的 `baseline_proof`，也不接入恢复会话的设备写入口。大容量设备的完整内容扫描由单独只读检查执行，不能把目录/大小或抽样相同当作完整内容一致。

## 事务与持久记录

事务保留经过独立解析验证的旧/新库和内容指纹。先持久保存恢复依据，再修改目标；恢复记录带版本、长度边界和校验和，损坏或不一致时拒绝自动恢复。校验和检测偶发损坏，不宣称能抵抗恶意本地修改。

新库在电脑侧只生成一次并独立验证，可在复制前完成，以便在任何介质变更前冻结全部预期产物；随后复制音频、Flush/大小检查、同目录改名，再暂存数据库。此顺序采用 BP-FLOW-002 的电脑侧预验证，不降低 SAFETY_MODEL 的“先音频落盘、后提交数据库”要求。

目标旧库改为事务备份名，新库改为正式名。每次改名不宣称 FAT32 掉电原子性。正式路径重新读回验证后才允许删除计划中明确列出的、不再被新库引用的旧音频。任何未知文件均不删除。

在首次重命名前额外持久化提交意图；初始化在没有该记录时恢复为空库缺失状态，不擅自提交已取消的初始化。完成标记绑定最后选定的数据库指纹，旧事务不得在后续批次之后再次运行旧清理动作。重复无变更请求不写任何文件。

设备身份在各文件操作前核对；移除/代次改变停止 I/O，不追踪旧盘符。重连恢复需要相同物理身份与当前有效代次，由新的恢复请求开启。

## 恢复判定

恢复不按时间猜“最新”。只接受记录绑定且内容/结构/签名/引用验证通过的旧、新候选。正式文件等于有效新库时保留新库；正式文件等于旧库时保持旧库；正式库缺失时优先恢复已验证旧库（初始化没有旧库，则可采用已验证的新临时库）。正式文件为未知内容、身份不匹配、所有候选无效或引用缺失时保持 RecoveryRequired，保留证据，不覆盖未知数据。

恢复可重复执行；恢复自身中断后仍使用同一证据。只清理可证明属于本次事务、内容符合记录且未被选中库引用的文件。未完成短文件可留作待清理，不因 .tmp 扩展名就删除。提交后删除失败只产生 CleaningRequired，不回滚已经有效的新库。

## 备份

电脑恢复仓库按设备不透明键隔离；不把私人绝对路径或歌曲名称写入公开日志。首次完整基线验证器检查外部目录与源清单的相对路径、大小和 SHA-256，一次完整读回只在首次基线验证使用。

当前基线接口只验证调用方提供的完整路径清单，执行前后对源内容复核；不自行创建或覆盖备份。清单是否完整、目录是否真正位于设备外、物理身份是否匹配仍由未来设备适配层负责，不得仅凭清单比较通过就开放真实写入。事务 manifest 含恢复必需的相对媒体路径，只能保存在本地私有仓库，不能把“无公开序列号”误称为可以公开发布。

保留最近 10 个有效快照，额外保护仍在使用的恢复点及至少一个 Last Known Good，必要时允许超过 10 份。电脑解析通过不自动代表设备播放通过；Last Known Good 由已确认基线或明确验收指定，新提交不会自动顶替它。损坏快照不参与有效计数，也不自动删除唯一恢复证据。

没有已确认 LKG 时暂停自动轮换，保护现有证据。事务前/后快照自动写入独立仓库；未完成恢复点被标为使用中。manifest 和事务旧/新库是另一层恢复证据，本轮不自动删除其历史文件，不能声称 10 个快照限制了全部占用；完整历史清理入口仍属后续备份管理能力。

## 验证范围

正常：初始化、更新、音频先于 DB、删除晚于 DB、无操作计划、完整基线、10 份轮换及 LKG。

故障：磁盘满、权限、短写、Flush、每个重命名点、数据库篡改、恢复记录损坏、身份/代次/能力变化、重复请求、各阶段取消、恢复反复执行及恢复自身中断。所有变更点使用异常模拟进程崩溃后重建服务，不能仅测试成功路径。

电脑目录不模拟 USB 控制器或固件，不将其通过结果称为真实 FAT32 断电、设备播放或 UI 验收。

## 2026-09-23 自动关联阶段

启动、刷新与重连在后台扫描当前实例 profile 下的 FooPodBridge/recovery 私有仓库。经正向识别和卷映射校验的物理身份经规范化和 SHA-256 生成带版本前缀的仓库键；它只定位私有资料，与数据库签名输入分离，不使用盘符、显示 token 或挂载代次作永久键。代次与 revision 继续控制扫描结果有效期。物理身份不可证明、映射冲突或不同物理设备重复身份均不关联。没有仓库不自动创建目录；访问失败与无记录分开呈现。扫描只读，按设备键检查主机事务 manifest 和数据库快照，不自动恢复、不授权写入。设置页通过现有状态说明展示扫描结果，不输出私有路径与身份。外部备份登记只能来自已验证基线，持久记录只用于下次定位，不能代替当次基线验证。

对于要求 hash58 的家族，缺少有效签名输入时仍可只读查看该物理设备的事务记录和已登记备份，但数据库快照及 Last Known Good 的有效性检查必须明确标为暂缓；不得显示为 0 个已验证快照、把暂缓误报为仓库访问失败，或允许从这些快照恢复。取得签名输入后重新扫描并完成结构与签名验证，才能报告可验证的快照数量；这仍不构成实机写入授权。
