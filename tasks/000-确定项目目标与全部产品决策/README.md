# 000-确定项目目标与全部产品决策

- 状态：已验收；2026-09-10 按设备目标范围重开并完成修订
- 日期：2026-08-28；2026-09-10 重开
- 当前产物：全非 touch 设备目标、架构、安全模型、总规格、决策清单和批准路线
- 实现授权：无；本任务禁止 C++、构建、组件、部署和实机写入

## 1. 任务目标

把已经确认的想法和所有仍会改变产品行为的选择写入仓库，使后续会话不依赖聊天记录，并让用户亲自批准完整任务路线。Codex 负责技术调查、方案、代码和测试；用户负责产品取舍、真实设备风险授权和人工验收。

## 2. 已批准方向

- 全新 x64 混合重建；
- Core 与 foobar/UI 分离；
- FooPodBridge/FooCrate 双组件服务边界；
- 所有能被 Windows 暴露为可访问存储卷的非 iPod touch 都属于强制目标并默认自动识别；早期 iPod、Shuffle、Nano 5+ 各自进入正式家族路线；
- 写入严格按证据等级开放，未知或未实现 profile 保持只读；实机只验证对应格式/能力，不成为产品专用配置；
- 纯手动 Music/Audiobook 管理，无 Sync；
- SoundCheck、Classic gapless 和原生 Smart Playlist 编辑器进入正式目标；
- FAT32 性能感知的批次事务；
- FooCrate UI 优先，详细视觉稿到 UI 任务；
- AI 使用 `foobar-dev`，用户使用 `foobar-test`，C 盘日常安装禁止触碰；
- 最终输出两个独立 `.fb2k-component`。
- 直接复制按设备能力矩阵判断，首批验证 MP3、AAC-LC/M4A 和设备确认支持的 ALAC；不支持项目逐项显示且不影响兼容项目；
- 重复项强匹配并默认 Skip，允许 Add duplicate；Replace metadata 等待后续测试重新决定；
- 独立单曲问题警告并继续，关键设备/空间/数据库/事务错误停止批次；导入后保留可调但非零的安全余量。
- 元数据读取 foobar 正式原始字段，核心字段完整、次要字段尽力写入；缺少 ReplayGain 不自动扫描，封面使用 artwork service；
- Music/Audiobooks 由用户明确选择导入目标，第一版可在统一 Library 管理两种 Media Kind，不根据扩展名或 Genre 偷猜；
- Compilation 明确标签优先；缺失时按统一 Album Artist + Album 且存在不同 Artist 自动推断，并合并本次、设备与 foobar 曲库证据。
- Playback Statistics `%rating%` 是电脑端唯一评分来源；导入或明确刷新时单向写入设备，缺失评分清空设备 Rating，设备端改动不反写电脑；
- foobar 普通/autoplaylist 对象不传输到设备；普通设备 playlist 由明确 New 创建后加入曲目，原生 Smart Playlist 只通过规则编辑器创建和编辑；
- Smart Playlist 只有实机确认的组合显示 Live；删除明确区分移除引用与删除设备曲目，空 playlist 默认保留。
- 首版用户可见文案与 FooCrate 一致使用英文；独立 Columns UI 保持完整功能，Default UI 使用简化入口和共享 Smart Playlist 管理对话框；所有入口均不提供 Eject。
- 诊断使用本地有界、默认脱敏、用户主动导出并可预览的方案；候选包只在形成可人工验证的永久能力时输出。
- FooCrate 保持 MIT；FooPodBridge 计划采用 `LGPL-3.0-or-later`，最终 SPDX 与复用边界由任务 001 文件级审计确认；共享服务合同使用原创宽松许可。

完整记录见 [`USER_DECISIONS.md`](../../decisions/USER_DECISIONS.md) 第 2 节。

## 3. 明确不做

- 不创建 CMake、C++ 或组件工程；
- 不生成空面板、假设备或演示 UI；
- 不启动、部署或控制任何 foobar2000；
- 不连接、读取或写入真实 iPod；
- 不从 `Ref` 复制源码或二进制；
- 不决定用户尚未核对的产品行为；
- 不把建议路线冒充已批准实现计划。

## 4. 可检查步骤

### 步骤 1：核对总目标与排除范围

- 输入：[`PRODUCT_GOAL.md`](../../docs/PRODUCT_GOAL.md)、[`PRODUCT_SPEC.md`](../../specs/PRODUCT_SPEC.md)。
- 动作：用户检查目标是否等于自己实际想长期使用的产品。
- 产物：目标、正式设备、功能与排除范围获得批准或修订。
- 检查方法：重点检查 Music/Audiobook、无 Sync、无播放次数同步、SoundCheck、gapless、Smart Playlist 和三套 UI。
- 通过标准：总目标没有默认继承用户不需要的 foo_dop 功能。
- 状态：已完成；2026-09-10 按全非 touch 目标重新核对。

### 步骤 2：核对架构与双组件边界

- 输入：[`ARCHITECTURE.md`](../../docs/ARCHITECTURE.md)。
- 动作：用户确认独立 Core、服务合同、FooCrate 消费者和 UI 责任。
- 产物：任何后续任务都不能把数据库逻辑写进 UI 或复制进 FooCrate。
- 检查方法：确认 FooPodBridge 单独安装可用、FooCrate 缺服务时隐藏 Devices。
- 通过标准：依赖方向和两个包的职责清楚。
- 状态：已完成；家族注册表、FormatPending 和证据门禁已写入正式架构。

### 步骤 3：核对事务与性能

- 输入：[`SAFETY_MODEL.md`](../../docs/SAFETY_MODEL.md)。
- 动作：用户检查备份、导入/删除顺序、批次 DB、USB 写一次、取消和中断结果。
- 产物：不可关闭的安全硬规则与需要用户选择的备份/清理项。
- 检查方法：确认安全没有把正常音频复制时间翻倍，并且任意中断优先保留旧 DB。
- 通过标准：核心原则批准；`DEC-SAFE-*` 逐项完成。
- 状态：核心原则和开发/实机测试阶段细节已批准；正式日常版前重开首次完整基线门槛与数据库快照数量。

### 步骤 4：完成第一轮实机与直接导入决定

- 输入：`EVID-DEV-001/002`、`DEC-IMP-001` 至 `DEC-IMP-006`。
- 动作：用户提供非隐私设备信息并选择格式、错误、重复、批次和空间规则。
- 产物：device/media/transaction 可以建立无歧义模块规格。
- 检查方法：用用户真实 MP3/AAC/ALAC/FLAC 情况验证选择是否符合日常使用。
- 通过标准：第一轮所有待决定项批准或排除；设备证据采集方法确定。
- 状态：产品决定已完成。`DEC-IMP-001/002/004/005/006` 已于 2026-08-26 批准；`DEC-IMP-003` 明确延后且当前不自动转码。各 `EVID-DEV-*` 继续作为对应实机写入任务的设备级门槛，不再作为任务 000 或其他家族进入目标范围的门槛。

### 步骤 5：完成元数据与 Audiobook 决定

- 输入：`DEC-META-001` 至 `DEC-META-007`。
- 动作：用户选择 metadb、SoundCheck 缺值、封面、Audiobook、缺失标签、Compilation 推断和 Playback Statistics Rating 单向导出行为。
- 产物：完整导入字段、分类、Compilation 和失败行为。
- 检查方法：用一首普通音乐、一张有/无封面专辑和一个有声书样本走计划。
- 通过标准：第二轮全部批准或排除。
- 状态：已完成。`DEC-META-001` 至 `DEC-META-007` 已于 2026-08-26 批准；详细 UI 入口仍按计划留到对应 UI 任务冻结。

### 步骤 6：完成 playlist、Smart Playlist 与删除决定

- 输入：`DEC-PL-002` 至 `DEC-PL-006`。
- 动作：用户选择 playlist 冲突、foobar autoplaylist 快照、非实时 Smart 规则和删除语义。
- 产物：普通/Smart playlist 与删除模块无歧义。
- 检查方法：分别演练“只从列表移除”和“从设备彻底删除”。
- 通过标准：第三轮全部批准或排除。
- 状态：已完成。`DEC-PL-002` 至 `DEC-PL-006` 已于 2026-08-26 批准；相关 Rating 来源、单向刷新和 Smart Playlist 用法已由 `DEC-META-007` 冻结。

### 步骤 7：完成备份、恢复与生命周期决定

- 输入：`DEC-SAFE-003` 至 `DEC-SAFE-008`。
- 动作：用户选择外部备份、保留、清理、取消、多设备和外部移除边界。
- 产物：实机写入前可执行的恢复与隐私策略。
- 检查方法：确认备份不在 iPod 本身，且用户能找到和恢复。
- 通过标准：第四轮全部批准或排除。
- 状态：已完成。`DEC-SAFE-003/004` 已按开发与实机测试阶段采用 A、正式日常版前重开；`DEC-SAFE-005/006/007/008` 已于 2026-08-26 批准。

### 步骤 8：完成 UI、诊断、许可证与发布决定

- 输入：`DEC-UI-*`、`DEC-DIAG-001`、`DEC-LIC-001`、`DEC-PKG-002`。
- 动作：用户确认语言、独立 UI 范围、诊断隐私、许可证和候选节奏。
- 产物：UI/发布路线和合法复用边界。
- 检查方法：详细 FooCrate mockup 按决定留到任务 006/018，不在本任务强迫预画。
- 通过标准：第五轮当前阻断项全部批准或明确延后到指定 UI 规格任务。
- 状态：已完成。`DEC-UI-004/005/006`、`DEC-DIAG-001`、`DEC-LIC-001` 与 `DEC-PKG-002` 已于 2026-08-28 批准；`DEC-UI-003` 的详细信息结构按原决定延后到 UI 任务。许可证的最终 SPDX 与文件级复用边界在任务 001 审计确认。

### 步骤 9：批准完整路线

- 输入：[`tasks/TODO.md`](../TODO.md)。

## 6. 验收标准

- 新会话只读仓库即可准确复述目标、架构、设备风险、测试边界和下一步；
- 所有已批准聊天决定在一个明确位置有记录；
- 所有未批准行为都有推荐方案、替代方案、影响和状态；
- 产品规格、架构、安全模型、UI 方向和路线互相一致；
- 文档为严格 UTF-8 无 BOM、LF，本地 Markdown 链接有效；
- 没有 C++、构建输出、组件、部署或设备修改；
- 用户明确核对后才进入任务 001。
